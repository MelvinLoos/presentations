Analyse & feedback // vraag 1 — antwoord B

In WebXR betekent een minder negatieve Z-waarde dat het object dichter naar de kijker beweegt.

Vooraanzicht — camerabeeld

Zijaanzicht — de camera kijkt richting −Z

[08:00 – 10:00] Koppel terug op de Mentimeter-resultaten: "Ik zag dat X% voor C koos. Wie kan uitleggen waarom C logisch voelt?" Klik daarna de drie stappen in: 1) X — links is min, rechts is plus. De bal staat op -2 en moet daar blijven, dus D valt af. 2) Y — in 3D is Y altijd de hoogte. Van 0 naar 2 is twee meter omhoog, dus A (Y = -3) valt af. 3) Z — de camera kijkt standaard de -Z richting in. Hoe negatiever Z, hoe verder weg. Van -6 naar -3 is dus drie meter dichterbij; -9 (optie C) is juist drie meter verder weg. Benadruk het verschil met 2D-web: in CSS heb je alleen X en Y, gerekend vanaf linksboven, en loopt Y naar beneden. In een 3D-ruimte is Y altijd de hoogte (omhoog is plus) en gaat Z de diepte in. Ezelsbruggetje: +Z wijst naar jou toe, uit het scherm.

Analyse & feedback // vraag 3 — antwoord A

Elke 3D-interactie doorloopt de keten van raycasting, event-detectie en component-mutatie.

1 // Waarnemen

Input & raycast

De cursor schiet een onzichtbare lijn vanuit het midden van het scherm (of de controller) en detecteert waar je naar kijkt of klikt.

<a-cursor>
2 // Luisteren

Event listener

Een listener op de entity vangt de actie op in de DOM: 'click', 'mouseenter'.

entity.addEventListener('click', …)
3 // Veranderen

Component-mutatie

Je past een component real-time aan: kleur, positie, een animatie of een geluid.

entity.setAttribute('color', …)
Jouw kettingreactie 

schelp.addEventListener('click', () => {   // 2. luisteren
  lucht.setAttribute('color', '#1B1F3B');   // 3. veranderen
  onweer.components.sound.playSound();      // 3. veranderen
});
[16:00 – 17:30] Klik de keten stap voor stap in. 1) Waarnemen: de cursor is een raycaster. Hij schiet een onzichtbare straal en weet zo welk object je raakt. Zonder deze stap is er geen event (dat was de eerste bug). 2) Luisteren: precies zoals op een gewone webpagina met addEventListener, maar dan op een 3D-entity. 3) Veranderen: niet via CSS, maar door een component te muteren met setAttribute, of door een animatie of geluid te starten (dat was de tweede bug). Verbind dit met hun eigen project: wie had in Het Zintuiglijke Strand een kettingreactie gebouwd, bijvoorbeeld klik op schelp → lucht wordt donker → onweergeluid start? Dat is exact deze drietrapsraket (laatste fragment). Deze keten bestaat in elke engine, ook in Unity: input → event → state change.

In A-Frame-code: <a-entity light="type: directional; castShadow: true" position="-5 4 2"></a-entity> <a-entity gltf-model="#vuurtoren-glb" shadow="cast: true"></a-entity> <a-plane ... shadow="receive: true"></a-plane> <a-entity position="4 0 -8" sound="src: #knetter; autoplay: true; refDistance: 2; rolloffFactor: 3"></a-entity> (castShadow/receiveShadow zijn de namen in Three.js. Waarom ambient light nooit een schaduw kan werpen: het komt van alle kanten tegelijk, dus er is geen richting en daardoor geen "achterkant" waar een schaduw kan vallen (optie A). Audio in 3D hangt aan een plek in de ruimte: hoe verder je wegloopt, hoe zachter het klinkt. Een gewone <audio>-tag klinkt "in je hoofd", als achtergrondmuziek. Volume op 10% (C) is overal even zacht, en een grijze vlek is nep-schaduw die niet meebeweegt met licht of objecten. D: niets gaat automatisch, schaduw moet je expliciet aanzetten op licht én objecten. Let ook op de autoplay-restrictie van browsers: geluid start pas na de eerste gebruikersinteractie (klik/tik). Start geluid daarom bijvoorbeeld in een click-handler met el.components.sound.playSound().
